# Native rendering interpolation up to 360 Hz

Status: design only; no interpolated frames are generated by this commit.

## Quality requirements

- Interpolate render transforms and animations; do not blend completed images.
- Keep simulation, collisions, input, audio and save logic at their existing cadence.
- Expose an off-by-default presentation target up to 360 Hz independently of gameplay FPS.
- Preserve crisp HUD/text and original textures; do not interpolate HUD geometry as world objects.
- Reset history on scene changes, camera cuts, teleports, model destruction and resource reloads.
- Meet presentation deadlines without speeding up or slowing down the simulation.

## Implementation order

1. Separate render snapshots and presentation scheduling from simulation. The current
   GX display-copy callback presents synchronously; JDrama::TVideo::waitForRetrace also
   waits unconditionally for a VI retrace. A burst of swaps inside GXPC_Present would
   consume simulation time, so it is not a suitable implementation.
2. Capture stable model identities, previous/current world and joint transforms,
   camera pose/projection and render-only animation data. J3DModel::viewCalc currently
   concatenates view and skeletal matrices; capture before this concatenation.
   Never pair objects by draw-call number: culling and transparent sorting change order.
3. Render intermediate geometry using interpolated translation/scale and quaternion
   rotations. Recalculate normal matrices and billboards. Preserve object lifetimes
   through snapshot ownership; never mutate gameplay state while rendering snapshots.
4. Handle Mario, J.E.T. water, particles, changing topology, shadows and EFB texture
   copies explicitly. Unsupported effects must retain correct rendering rather than
   borrowing another object's history. Treat screen-space menus separately.
5. Add live menu settings and persist the target. Keep VI timing unchanged.
   Disable interpolation for headless/deterministic operation and reset on resize.
6. Validate camera rotation, occlusion, water spray, scene transitions and HUD at
   30/60 simulation FPS and multiple output targets through 360 Hz. Record actual
   presented frames, CPU/GPU time and missed deadlines. A 360 Hz target does not
   guarantee that the display or GPU can deliver 360 distinct visible frames.

## Existing native frontend

This commit also preserves the previously built PAL menu/live settings and service
integrations. RetroAchievements login/listing is implemented; native memory mapping
and achievement evaluation remain incomplete. No online multiplayer is enabled.
